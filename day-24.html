Day 24GHL API 2.0 in n8n

Yesterday data flowed GHL → n8n. Today you learn the other direction: n8n calling into GHL through its API 2.0. 0% of today's tasks complete

Session 1 — API crash course in plain language

≈ 1 hour

Thirty minutes of vocabulary, zero code. An API is just a website for programs instead of people: you send a structured request, you get structured JSON back. Everything you do today is filling in four blanks: where (URL), what kind (method), who you are (headers), what data (body).

Session 2 — Token, locationId, and your first authenticated call

≈ 2 hours

Session 3 — The four drills: search, create, update, tag

≈ 2.5 hours

Duplicate the HTTP Request node for each drill (select it → Ctrl/Cmd+C, Ctrl/Cmd+V) so the credential and Version header come along. Wire each copy to the Manual Trigger and use Execute Node on one at a time.

Session 4 — Mini-lab: webhook in, GHL contact out

≈ 1.5 hours

Glue the week together: an n8n endpoint that anyone (or any system) can POST a lead to, which creates the contact in GHL and replies with the new contact ID. This exact shape — receive → call GHL API → respond — is the skeleton of Days 25–27.

📦 Deliverable of the day

A Private Integration token with correct scopes stored as a reusable n8n Header Auth credential, four verified raw API calls against Summit Dental (search by email, create contact, update custom field by ID, add tag), a working Contact Creator API workflow tested on both test and production URLs, two workflow JSONs in GHL Portfolio/n8n-exports, two screenshots, and your status-code debugging cheat-sheet in the journal.

⚠️ Watch out

Treat the pit- token like a password: never paste it into a workflow field (credential only), never screenshot it, and remember it grants live write access to the sub-account. If you ever leak one, delete the Private Integration in GHL and create a new one — that rotates the token instantly.
