Day 10Portfolio M5: Automated Report Generator

By tonight, every Monday at 08:00 a scenario will read a sales sheet, compute totals and per-status breakdowns with aggregators and mapping functions, fill a Google Docs template, convert it to PDF, email it with the PDF attached, and archive a copy to Drive. "The Monday report writes itself" is one of the easiest automations to sell — and it exercises the aggregation and formatting muscles every client project needs.

Session 1 — Sample data and the Docs template

≈ 1.5 hours

Reports are template work: the document layout lives in Google Docs with {{placeholder}} tags, and Make just fills the blanks. Build both ingredients — realistic data and a clean template — before touching the canvas.

Session 2 — Aggregate: from 30 bundles to one set of numbers

≈ 2.5 hours

The heart of the build. In Make, 30 rows arrive as 30 bundles; a report needs ONE bundle holding totals. That's the Array Aggregator plus the map() / sum() / length() function trio — the exact opposite direction of Day 2's iterators.

Session 3 — Docs merge, PDF, email, archive

≈ 2 hours

Four modules in a row: fill the template, download it as PDF, email the PDF, archive it. Each one is a connector you'll reuse in dozens of client builds.

Session 4 — Test, break, cost, package

≈ 1 hour

📦 Deliverable of the day

The [M5] Weekly sales report scenario producing a client-clean PDF verified against the sheet, the template Doc with exact {{tags}}, a per-product breakdown built with deduplicate → Iterator → Text Aggregator, an operations-cost estimate vs. actual in the journal, and blueprint + screenshots + Loom in the portfolio folder.

💡 Sell the template, not the scenario

When you demo this build, lead with the Google Doc: "you can restyle this report yourself, any time, without touching the automation." Separating layout (client-editable) from logic (yours) is what makes report generators low-maintenance — and low-maintenance is what clients renew.
