Session 1 — Routers: one bundle in, many roads out

≈ 1.5 hours

A Router splits the flow into parallel routes. Critical mental-model correction for n8n users: a Make router is NOT an IF/Switch node. It copies every bundle down every route, in order, top to bottom — the per-route filters are what make it behave like a switch. No filter on a route = every bundle travels it.

Session 2 — Filter operators lab: text, numeric, exists, date

≈ 1.5 hours

The operator dropdown in every filter has grouped sections — Text, Numeric, Date/Time, Boolean, Array, plus Exists / Does not exist. Picking from the wrong group is the #1 silent filter bug in Make, because everything coming out of a sheet or webhook is a string until an operator says otherwise.

Session 3 — Error handlers: all five directives, hands on

≈ 2 hours

When a module throws an error and nothing handles it, the run stops, the whole thing is rolled back where possible, and after enough consecutive failures Make disables the scenario. Error handlers are transparent routes hanging off a module that decide what happens instead. You'll force a real error and attach every directive to it, one by one.

💡 The interview answer

"How do you handle errors in Make?" — the answer that lands: "Depends on whether the failure is skippable, substitutable, or transient." Skippable → Ignore. Substitutable → Resume with defaults. Transient → Break with retries and stored incomplete executions — plus an alert module on the handler route so a human knows. Saying those three words with a directive each is a hire signal.
