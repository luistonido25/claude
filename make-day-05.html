Day 5HTTP Module & APIs

By tonight you'll call any API on the internet from Make — with query parameters, headers, API keys, and JSON bodies — page through multi-page results with a Repeater, respect rate limits with Sleep, and keep a scheduled "morning API digest" scenario as evidence. This one skill is what lets you say yes when a client's tool has no built-in Make app.

0% of today's tasks complete

Session 1 — Anatomy of a request, against a live API

≈ 2 hours

The HTTP > Make a request module is the universal adapter: when there's no app module for a service, this is how you talk to it anyway. A request has five parts — URL, method, headers, query string, body — and you'll exercise each against Open-Meteo, a free weather API that needs no key at all.

Session 2 — API keys, headers, and when to use connections instead

≈ 1.5 hours

Most useful APIs want to know who's calling. The three common schemes: a key in the query string, a key in a custom header, or a token in the Authorization header. You'll do the first live against NASA's free API and set up the other two as written patterns.

Session 3 — Pagination and rate limits

≈ 1.5 hours

Real APIs never hand you everything at once — they paginate. Two shapes in the wild: page/offset parameters you increment, or a next URL you follow. You'll drill the first shape with a Repeater against the free PokéAPI (no key), and learn the politeness tools for the inevitable 429.

Session 4 — Mini-build to keep: the Morning API Digest

≈ 1.5 hours

Not a portfolio headliner, but permanent evidence that you can consume APIs on a schedule and turn them into something a human wants to read. Fifteen modules of skill in a five-module scenario.

📦 Deliverable of the day

A working HTTP lab (keyless API, keyed API, forced 404/403 reads, Repeater pagination over 3 pages), the scheduled Morning API Digest emailing real weather + space data, two exported blueprints, screenshots, and the status-code + auth-scheme vocabulary written from memory.

💡 The client-call superpower

When a client says "we use SomeObscureTool, does Make support it?", the professional answer is never "no". It's: "Does it have an API? Then yes." Today's module is why. Keep the NASA and Open-Meteo calls in your HTTP lab blueprint — walking someone through a raw API call from a blank canvas is a devastating interview demo.
