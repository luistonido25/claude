Session 1 — Data stores: the five record modules

≈ 2 hours

A Data store is a small key-value database living inside Make — no external service, no API latency, made for lookups mid-scenario: "have I seen this email before?", "what record ID maps to this row?". A data structure defines its columns. You get limited storage per plan (the free plan's allowance is tiny but plenty for ledgers).

Session 2 — The classic dedupe pattern

≈ 1.5 hours

The most-billed five modules in freelance automation: input → search ledger by key → filter "not seen" → add to ledger + continue → duplicates die cheap. Once you can build this cold, every "our tool keeps double-sending" client problem is a payday.

Session 3 — Text parser: three regex drills

≈ 1.5 hours

Real-world text is sludge: emails buried in signatures, phone numbers formatted nine ways, names in one field that should be two. The Text parser > Match pattern module runs a regular expression over text and outputs the captures as chips — one bundle per match when Global match is on.

Session 4 — Tools tour + Lead Intake Machine v2

≈ 2 hours

First a fast, honest tour of the Tools family you haven't formally met — then the day's keeper build: import your Day-4 blueprint and bolt the dedupe gate in front of it. Same machine, professional-grade behavior.

📦 Deliverable of the day

💡 Where the data belongs — the 5-second decision

Client will read it → Sheet/Airtable. Only the scenario needs it → Data store. Only this run needs it → variable. Say that rule out loud in interviews and you sound like someone who's cleaned up other people's messes. Tomorrow raises the stakes: the two-way sync uses a data store as a ledger holding record-ID mappings and change-hashes — everything from today, load-bearing.
