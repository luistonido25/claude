Day 11Portfolio M6: Order & Ops Flow

Today you build the closest thing to real e-commerce plumbing without a store: a webhook receives order JSON (with a line-items array — hello, iterator), a router splits VIP from standard orders, a Docs template turns line items into an invoice, a fulfillment row lands in Sheets, confirmation emails go out — and a second webhook handles refunds with an apology email and an ops alert. Two scenarios, one believable business.

0% of today's tasks complete

Session 1 — The fake storefront: webhook + three sample orders

≈ 1.5 hours

No storefront needed: a Custom Webhook plus curl IS your storefront. The payload below is deliberately shaped like what real cart platforms send — nested customer object, items array, numeric total.

Session 2 — Iterator → Text Aggregator → invoice from template

≈ 2.5 hours

The invoice is the technical heart: line items live in an array, but a Docs template wants one text block. The recipe — Iterator to explode the array, Text Aggregator to fold it into formatted lines — is the same pattern behind every "list of things inside one document/email" job you'll ever quote.

Session 3 — Fulfillment row, VIP router, confirmation emails

≈ 2 hours

Session 4 — The refund branch + full end-to-end run

≈ 1.5 hours

Ops flows earn their keep on the unhappy path. A second webhook receives refunds, finds the original order in the sheet, flips its status, apologizes to the customer, and alerts ops — including the case where the order ID doesn't exist.
